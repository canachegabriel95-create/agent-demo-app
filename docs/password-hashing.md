# Password hashing and the `hash-password` CLI

Passwords are never stored in plain text. The API and the command line tool share **one** implementation, `IPasswordHashingService` (`ContentReview.Domain.Security`), implemented by `PasswordHashingService` (`ContentReview.Infrastructure.Security`). It wraps `PasswordHasher<User>` from `Microsoft.Extensions.Identity.Core` (ASP.NET Identity V3 format: PBKDF2-HMAC-SHA512, random salt, 100 000 iterations by default). Full ASP.NET Identity is not used. A hash generated by the CLI is therefore accepted by login in the API.

The service is registered by `AddInfrastructure()` as a singleton.

## Password policy

Defined once in `PasswordPolicy` (Domain) and enforced by the CLI (and by registration, F05):

- 12-128 characters
- at least one uppercase letter, one lowercase letter, one digit and one symbol (a character that is not a letter, a digit or white space)

The rules, their names and the Author Portal mirror are described in [business-rules.md](business-rules.md#passwords).

## Generating a hash

```bash
# Interactive: the password is typed without echo and must be confirmed.
dotnet run --project backend/tools/ContentReview.Tools -- hash-password

# Automation: the password is the first line of standard input.
read -rs ADMIN_PASSWORD
ADMIN_PASSWORD_HASH=$(printf '%s\n' "$ADMIN_PASSWORD" | dotnet run --project backend/tools/ContentReview.Tools -- hash-password --stdin)
```

```powershell
$hash = $plainPassword | dotnet run --project backend/tools/ContentReview.Tools -- hash-password --stdin
```

Behavior:

- Standard output contains **only** the hash (one line), so it can be captured. Prompts and messages go to standard error.
- The password is never logged or written to a file. Do not pass it as a command-line argument; it would end up in shell history.
- Piped input requires `--stdin`; without it the tool refuses instead of waiting for a terminal.

| Exit code | Meaning |
|---|---|
| 0 | Hash printed |
| 1 | Password violates the policy; the rules are listed on stderr and nothing is printed on stdout |
| 2 | Input error (empty stdin, redirected input without `--stdin`, mismatched confirmation, cancelled) |

The generated hash is supplied to `db/scripts/provision-admin.sql`; see [admin-provisioning.md](admin-provisioning.md).

## Tests

- `PasswordHashingServiceTests`: round trip, wrong password, salting, Identity V3 / HMAC-SHA512 marker, invalid hashes.
- `PasswordPolicyTests`: every rule and the length boundaries.
- `HashPasswordCommandTests`: only a verifiable hash on stdout, exit codes, rule listing, password never echoed to either stream, `--stdin` and interactive modes.
